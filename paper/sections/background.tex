The basic DVS model describes each pixel as a detector of changes in log intensity. A positive change reaching the ON threshold produces an ON event, while a negative change reaching the OFF threshold produces an OFF event. After an event, the pixel updates its reference level, and a refractory period limits how soon it can respond again~\cite{lichtsteiner2008dvs,gallego2022event}. This model connects changes in the visual stimulus to the events that a simulator must generate.


Real event pixels depart from this simplified conceptual model in several ways. Although the parameter $\theta$ is a useful concept, the user can only indirectly influence $\theta$ through the manipulation of abstracted `bias' settings.  Bias settings are specific to systems, not thresholds that are directly interpretable with physical measurements. The user-facing bias settings (e.g., bias\_diff\_on/off) are currents that shift circuit operating points, and their mapping to the effective $\theta$ is influenced by factors including factory trim, temperature, and photocurrent, that contradict the interpretation of bias as a static influence on luminance threshold \cite{graca2023biasing}. Matching nominal settings is therefore not sufficient to establish that a simulator and a real sensor have the same response.


% In a real event sensor, however, the effective contrast thresholds are not generally specified directly by the user. Instead, sensor-specific bias settings control circuit operating conditions, including sensitivity, bandwidth, and refractory behavior. Their effects depend on the pixel circuitry and illumination, so a numerical bias setting cannot simply be treated as a contrast threshold with a known physical meaning~\cite{graca2023biasing}. Matching nominal settings is therefore not sufficient to establish that a simulator and a real sensor have the same response.

Further differences arise because pixels do not respond identically or instantaneously. Threshold mismatch changes which brightness variations produce events, finite bandwidth and latency, and noise can generate events without the intended stimulus change. These effects also depend on illumination~\cite{hu2021v2e,graca2021noise}.

Existing simulators reproduce these effects to different degrees, and each focuses on a different part of the process. V2E converts video frames into events with a pixel model that includes intensity-dependent bandwidth, threshold mismatch, and noise.  To reduce the gap between the native video frame-rate and the extremely high potential refresh rate of a single event pixel, V2E begins with a process of frame-interpolation using the SuperSloMo network~\cite{hu2021v2e}, with several notable drawbacks. Most notably, conversion is slow. We found that it took over 50 minutes to convert 10 second video recording with a nominal frame rate of X fps, up to an effective nominal frame rate of Y fps (e.g., from N to M ms per frame) using an XYZ CPU with N megabytes of ram and an XYZ GPU. The greatest portion of this conversion was spent on the process of interpolating the original video stream. Despite the lengthy interpolation process, the resulting events still remain grouped around the interpolated frame times, as has been previously observed by Zhang et al.~\cite{zhang2024v2ce} and Han et al.~\cite{han2024pecs}. V2CE attempted to mitigate these effects by predicting the occurrence of events from consecutive frames~\cite{zhang2024v2ce}. Other researchers have taken qualitatively different approaches to capturing the temporal characteristics of the event sensor. DVS-Voltmeter uses pixel intensity values as input to a stochastic model of pixel-level voltage change influenced by randomized photon arrival time and added noise from temperature and parasitic photocurrent~\cite{lin2022dvsvoltmeter}.  In contrast, the Physical-based Event Camera Simulator (PECS) in which a 3D scene model of light transfer interacts with a pixel-level model of event sensor operation that is implemented as a novel rendering pipeline~\cite{han2024pecs}.

These simulators each address different known limitations, but their improvements are mostly evaluated by downstream task performance rather than by a direct comparison with real events. A direct comparison needs a representation of the event stream that does not depend on a particular application, and event streams naturally support this when represented as point sets. Each event provides a spatial location and a timestamp, with polarity as an additional attribute. After alignment and a choice of spatial and temporal scaling, the coordinates can be treated as points in a common space. In this study, we mainly compare three-dimensional space--time points. This representation measures the similarity of events directly, without requiring features learned for a downstream task, although it may not reflect performance differences in all applications. Because each event set is treated as a distribution with a fixed total, it also does not capture differences in event rate, which should therefore be reported separately.

With this representation, comparing real and simulated recordings becomes a comparison between two empirical distributions of event locations in space and time. The aim is to measure how these distributions differ under the chosen representation. A nonzero value does not by itself indicate a simulator error because finite samples from the same distribution can also differ, and repeated real recordings also may not be identical. This motivates the comparison between repeated real rotations, which serves as a noise floor in the evaluation. 
% ===== end of paragraph 5 =====

MMD measures the difference between two distributions through a kernel, which assigns a similarity to each pair of points~\cite{gretton2012kernel}. It compares the distributions' average representations in the feature space defined by that kernel. With a characteristic kernel, such as a Gaussian kernel, the population MMD is zero only when the distributions are equal. In a finite sample, however, the measured response depends on both sampling and the kernel bandwidth. The bandwidth determines the scale at which differences between event points contribute to the measurement.

Wasserstein distance provides another way to compare distributions by measuring the cost of transporting probability mass from one to the other. The movement cost is defined by distance in the chosen space. SWD uses projections onto one-dimensional axes, computes a Wasserstein distance along each projection, and combines these values~\cite{bonneel2015sliced}. This makes the comparison more tractable for large point sets. Our implementation uses the Python Optimal Transport library~\cite{flamary2021pot}; the projection settings and distance order are specified in the methodology.

Chamfer distance compares point sets through nearest neighbors and is commonly used for point clouds~\cite{fan2017pointset}. PECS used it to compare simulated and real events~\cite{han2024pecs}. For each point in one set, it finds the nearest point in the other set, and repeats the comparison in the opposite direction. We use the sum of the two mean Euclidean distances. Unlike Wasserstein transport, this procedure allows many points to share the same nearest neighbor without a constraint on the mass assigned to that neighbor. Because each event is compared only with its closest event in the other set, the value changes with the number of events as well as with their distribution. We therefore include it as an independent verification rather than as one of the main metrics.
% ===== end of paragraph 8 =====

Spike-train distances offer a related approach because events, like neural spikes, occur at discrete times. The van Rossum distance compares temporally filtered spike trains~\cite{vanrossum2001novel}, while SPIKE-distance measures differences in their timing structure~\cite{kreuz2013monitoring}. Applying these methods to event-camera data would also require a rule for handling spatial relationships. Pooling events into a single train discards their locations, whereas comparing corresponding pixels separately does not directly express how a small spatial displacement should affect similarity. We therefore focus on methods that operate jointly on spatial and temporal coordinates.

These methods provide different ways to compare event distributions, but how their distances relate to physical differences in our recordings still needs to be examined experimentally. We want the measurement to reflect spatial and temporal differences and background noise that change the event distribution, while remaining relatively insensitive to changes in event density that leave the underlying distribution unchanged.
